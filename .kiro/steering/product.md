# Product: Revenant

Revenant brings a dead website back as it actually was on a chosen date, and proves it.
Each restored file carries its capture time, source archive, digest, and a fidelity verdict.

## User
The person the site belonged to, or who must rely on it: a band member, a family member, a small business owner, a journalist or researcher citing what a page said on a given date.
Not SEO flippers. Paid restore tools already serve that market.

## Core flow (the Resurrection Ritual)
1. Paste a URL and pick a date.
2. Autopsy: Completeness and Fidelity scores, plus a per-file ledger.
3. Resurrection: the engine fetches and classifies files, then packages them.
4. Reveal: before/after, ZIP download, unlisted preview, certificate.

## Rules
- Never present a mocked or seeded result as live. Label every run LIVE or SEEDED.
- A failed lookup is UNKNOWN, never MISSING. "We could not ask" is not "it does not exist".
- Mark an anachronistic file as ANACHRONISM. Never hide it.
- The same input and the same capture set must produce the same ZIP hash.
- Do not add accounts, payments, dashboards, or analytics. They are non-goals (PLAN.md §10).
